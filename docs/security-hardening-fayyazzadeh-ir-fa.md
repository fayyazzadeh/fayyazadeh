## 4. پیاده‌سازی Rate Limiting در Preview

### 4.1 چرا Rate Limiting لازم است؟

Turnstile به تشخیص و کاهش درخواست‌های خودکار کمک می‌کند، اما جایگزین Rate Limiting نیست. محدودسازی نرخ درخواست تعداد دفعات فراخوانی API را در یک بازه زمانی کنترل می‌کند و می‌تواند از سوءاستفاده، مصرف بی‌رویه منابع و ارسال انبوه درخواست جلوگیری کند.

### 4.2 شاخه و Commit

شاخه:

`security/upstash-rate-limit-preview-2026-11-09`

Commit بررسی‌شده:

`577fd31b723bea7e0b52cf84e4154ece9a72132b`

این Commit شامل declaration نوع‌های TypeScript برای helper محدودسازی نرخ است. پیاده‌سازی کامل Rate Limit در تاریخچه همین شاخه قرار دارد.

### 4.3 حدود تنظیم‌شده

| مسیر/عملیات | سقف درخواست |
|---|---:|
| ارسال فرم تماس `/api/contact` | ۵ درخواست در دقیقه برای هر IP |
| درخواست چت `/api/wiki/chat` | ۲۰ درخواست در دقیقه برای هر IP |
| ایجاد تیکت پشتیبانی | ۵ درخواست در دقیقه برای هر IP |

ویژگی‌های طراحی:

- استفاده از شمارنده اتمیک در Redis برای جلوگیری از خطای هم‌زمانی.
- عدم ذخیره IP خام به‌عنوان کلید شمارنده؛ شناسه محدودسازی به شکل محافظت‌شده ساخته می‌شود.
- حفظ بررسی Turnstile و محدودیت اندازه بدنه درخواست.
- در صورت نبود یا از دسترس خارج شدن Redis، API به‌صورت fail-closed پاسخ 503 می‌دهد؛ یعنی درخواست بدون کنترل نرخ عبور نمی‌کند.

دو متغیر موردنیاز:

این متغیرها برای شاخه آزمایشی و محیط Preview تنظیم شدند. مقدار واقعی آن‌ها نباید در Git، فایل Markdown، Issue، Log یا پیام چت قرار بگیرد.

**نکته مهم:** مقدار Secret از طریق API قابل مشاهده نبود و در این مستند هم ثبت نشده است. اگر Token قبلاً در پیام یا محیطی غیرمطمئن افشا شده باشد، باید در Upstash باطل و جایگزین شود.

تست رفتاری کامل هنوز تأیید نشده است.

- دسترسی Preview ابتدا با SSO محدود شده بود.

## 5. بررسی Cloudflare

### 5.1 تنظیمات مشاهده‌شده

در زمان بررسی، وضعیت گزارش‌شده به این صورت بود:

| تنظیم | مقدار مشاهده‌شده |
|---|---|
| Plan | Free |
| SSL/TLS mode | Full |
| Always Use HTTPS | روشن |
| Automatic HTTPS Rewrites | روشن |
| TLS 1.3 | روشن |
| Minimum TLS Version | 1.0 |
| Browser Integrity Check | روشن |
| Security Level | Medium |
| HSTS در تنظیمات Cloudflare | خاموش |

برنامه Next.js به‌صورت جداگانه هدر HSTS ارسال می‌کرد. خاموش بودن HSTS در داشبورد Cloudflare با وجود هدر HSTS در پاسخ برنامه تناقض ندارد؛ این دو محل تنظیم جداگانه‌اند.

### 5.2 وضعیت DNS مشاهده‌شده

در بررسی DNS، وضعیت Proxy رکوردها به این شکل گزارش شد:

| نام رکورد | وضعیت مشاهده‌شده |
|---|---|
| دامنه اصلی (apex) | DNS Only |
| `www` | DNS Only |
| `mail` | Proxied |
| `smtp` | Proxied |
| `pop` | Proxied |
| `ftp` | Proxied |

این جدول فقط ثبت وضعیت زمان بررسی است و به معنی توصیه برای تغییر فوری رکوردها نیست.

### 5.3 اثر DNS Only روی حفاظت Cloudflare

وقتی رکورد وب DNS Only باشد، DNS پاسخ را به مقصد اصلی می‌دهد و ترافیک HTTP/HTTPS از Proxy کلادفلر عبور نمی‌کند. در نتیجه قابلیت‌های لبه مانند WAF و برخی کنترل‌های امنیتی Cloudflare روی آن ترافیک اعمال نخواهند شد.

برای استفاده از Proxy کلادفلر در کنار Vercel باید سازگاری DNS، گواهی TLS، مسیرهای دامنه، Redirectها و تنظیمات Vercel با دقت بررسی شوند. تغییر Proxy بدون برنامه بازگشت می‌تواند باعث اختلال در دسترسی سایت یا صدور گواهی شود.

### 5.4 هشدار رکوردهای ایمیل

رکوردهای `mail`، `smtp` و `pop` در snapshot بررسی‌شده Proxied گزارش شدند. Proxy معمولی Cloudflare برای پروتکل‌های ایمیل مانند SMTP و POP مناسب نیست، مگر آنکه سرویس و پیکربندی خاصی برای آن در نظر گرفته شده باشد.

از آنجا که سرویس ایمیل فعال است، این موضوع باید پیش از هر تغییری با بررسی رکوردهای MX، SPF، DKIM، DMARC و سرویس واقعی ایمیل بررسی شود. در این فعالیت هیچ رکورد ایمیل یا FTP تغییر داده نشد.

### 5.5 WAF و Managed Rules

- قواعد Managed Free Ruleset در Zone مشاهده شدند و مجموعه‌ای از قواعد مسدودسازی فعال در آن وجود داشت.
- مشاهده Managed Ruleset به‌تنهایی اثبات نمی‌کند که تمام درخواست‌های وب دامنه از Cloudflare عبور می‌کنند.
- در بررسی تنظیمات قبلی، WAF سفارشی/قواعد اجرایی مورد انتظار فعال گزارش نشده بود.
- به دلیل DNS Only بودن رکوردهای وب، حتی فعال بودن برخی قابلیت‌های لبه نیز بدون عبور ترافیک از Proxy برای سایت اثرگذار نخواهد بود.

|---|---|
| DNS Only | فقط پاسخ DNS؛ ترافیک از Proxy کلادفلر عبور نمی‌کند |
| Proxied | درخواست وب از شبکه Proxy کلادفلر عبور می‌کند |
| WAF | دیواره آتش برنامه وب برای شناسایی و مسدودسازی الگوهای حمله |
| Turnstile | ابزار Cloudflare برای تشخیص کاربر واقعی از ربات |
| Rate Limiting | محدود کردن تعداد درخواست در یک بازه زمانی |
| Redis | ذخیره‌ساز سریع داده در حافظه؛ در این پروژه برای شمارنده درخواست‌ها |
| Preview | نسخه آزمایشی جدا از سایت Production |
| Production | نسخه اصلی و در دسترس کاربران |
| Fail-closed | اگر کنترل امنیتی در دسترس نبود، درخواست پذیرفته نشود |
| HSTS | سیاست مرورگر برای استفاده از HTTPS در مراجعه‌های بعدی |
| Pull Request | درخواست بررسی و ادغام تغییرات کد |
